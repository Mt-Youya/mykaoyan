**What to build:** 管理员可以给账号手动开通会员（必须写原因），或批量生成兑换码；考生兑换后获得一年会员，会员期可以叠加；页面显示到期日。

**Blocked by:** 08（管理员角色与上下架）

**Status:** ready-for-human（会员开通与兑换、评论入口联动本地完成；投稿/评分联动待22–23，真机待验收）

- [x] 会员判断与会员期叠加为纯函数，有测试（未过期续期、已过期再开、跨年）
- [x] 不存「是否会员」字段，由会员期推算
- [x] 兑换码一次性；兑换与生成会员期在同一事务里；并发兑换同一个码只有一个成功（测试）
- [x] 管理员可查看兑换码是否已兑换、被谁兑换
- [ ] 非会员点击会员功能时看到开通说明（ticket 21已完成评论发表/回复入口及登录后会员面板路径，并经本地浏览器验证；投稿/评分仍待22–23，保留未核销）


## 本轮实现（2026-10-30）

- core/membership：纯函数以显式时刻计算，365天固定时长，左闭右开；连续叠加的会员期展示最终到期时间。覆盖未过期、过期后重开、闰年跨年和未来会员期。
- db：membership_periods 保存起止时刻、来源、手动原因/管理员或兑换码关联；redemption_codes 只存哈希、末四位与生成/兑换记录，不存完整兑换码。两表均 RLS + 公开角色撤权，会员状态不落库。
- API：会话取本人身份。管理员服务层重新查询当前角色；手动开通必须原因，兑换码批量1–100个、历史每页50个。兑换锁账号和兑换码，在同一事务内叠加会员期与标记兑换，code_id 唯一兜底。同账号并发手动开通/兑换不会重叠。
- 页面：现有登录页查看到期时间、兑换与展开说明；现有管理页通过手机号精确查找账号并手动开通、生成兑换码与分页看兑换账号。手机号只放 POST 请求体，查找仅返回编号。生成结果与历史共同显示唯一编号，避免末四位碰撞，完整码仅本次显示。
- 未实现评论、投稿、评分入口，不加入假功能按钮；入口权限和说明联动明确交由21–23，保留上方复选框未完成。
