# 个人信息保护影响评估：手机号出境到新加坡

> 状态：草案（2026-10-27）。本评估按《个人信息保护法》第五十五条、五十六条编写，覆盖本站在手机号验证码登录中把手机号存储到新加坡 Supabase Postgres 的处理活动。**待站主确认后定稿**；定稿前不应对外宣称已完成合规评估。

> **2026-10-30 核查：本草案不能作为当前生产环境的完成证明。** [部署记录](../ops/current-deployment.md)已写明生产数据库在东京，与本文的新加坡假设不一致；下文保留为原评估草案。需核对真实处理链路，连同社区内容、评分及媒体处理、接收方、权利渠道和保留/删除承诺重新评估后定稿，并同步登录告知与政策版本。详见[社区开放前核查](../delivery/community-launch-readiness.md)。

## 1. 处理活动

| 项 | 内容 |
| --- | --- |
| 处理者 | 网站站主（个人主体，ICP 备案主体） |
| 个人信息类型 | 手机号（11 位大陆号码，落库为 E.164），账号标识、会话、登录时间 |
| 处理目的 | 手机号验证码登录：识别账号、防刷、找回会话；不用于营销、不共享给第三方 |
| 处理方式 | 收集（用户主动输入）→ 阿里云号码认证发送与校验验证码 → 存储到新加坡 Supabase Postgres |
| 存储位置 | 新加坡（Supabase 项目区域）；境内只经过阿里云短信服务，不在境内落库 |
| 接收方 | 无。云服务商（Supabase、阿里云）作为受托处理者 |
| 保留期 | 账号存续期间保留；账号删除后 30 天内清除账号表与会话表；登录频率记录保留 30 天 |

## 2. 必要性

- 手机号是本站唯一的账号标识，业务上必须收集，不能匿名化替代。
- 登录必须验证是本人操作，因此必须向该号码发送验证码。
- 境内没有可用的自建数据库资源，部署在 Supabase 新加坡区域；因此手机号会出境。

## 3. 对个人权益的影响

- 手机号属于可识别自然人身份的信息，泄露后可能被用于骚扰或撞库。
- 出境后受新加坡法律与云服务商条款约束，与境内监管环境不同。
- 本站不收集真实姓名、身份证号、准考证号；不发布任何考生成绩或名单；不会因本处理活动产生对个人的差别待遇。

## 4. 保护措施

**收集与告知**
- 注册时单独勾选「同意个人信息存储在新加坡」，与用户协议分开，不默认勾选。
- 未勾选不能完成注册（前端禁用按钮，服务端返回 `CONSENT_REQUIRED`）。
- 记录同意时间与政策版本到 `personal_info_transfer_consents`，`(account_id, policy_version)` 唯一，重复同意幂等。

**最小化**
- 手机号只存于账号表的 `phone` 列；频率限制记录只存手机号的 HMAC 哈希，不存原文。
- 验证码由阿里云生成与校验，本站不保存验证码；Better Auth 的 `verification` 表不落库（`storeInDatabase: false`）。
- 日志与错误信息不打印手机号；对外提示统一为脱敏形式（`138****8000`）。

**传输与存储**
- 全站 HTTPS；到数据库使用 `sslmode=verify-full` 与事务连接池（端口 6543）。
- 数据库表启用 RLS，并撤销 `PUBLIC`、`anon`、`authenticated` 的表权限；所有读写只经 API 服务层。
- 云资源凭据只存于 GitHub Secrets 与本机受忽略的运行时配置，不进仓库。

**用户权利**
- 可以退出当前设备或所有设备；退出会撤销会话。
- 账号删除请求由站主手动处理（M1 阶段未做自助注销），处理时限 30 天。

## 5. 结论

- 处理目的明确、最小必要，已采取单独同意、最小化、加密传输与权限隔离措施。
- 出境人数预计远低于 10 万，且不含敏感个人信息；按《促进和规范数据跨境流动规定》，暂不触发出境安全评估申报。**若人数或信息类型发生变化，需重新评估。**
- 剩余风险：手机号作为唯一标识，一旦泄露影响面大；缓解手段是限定访问路径与不做二次分发。

## 6. 记录保存

本评估与同意记录至少保存三年（《个人信息保护法》第五十六条）。政策文案变更时升版 `PRIVACY_POLICY_VERSION`（当前 `2026-10-27`），并重做本评估。
