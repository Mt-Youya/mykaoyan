# 投稿分片由服务端核对，审核与文件清理分别留存

工单22要求会员在浏览器分片直传R2、断点续传、审核后上架，并在驳回满30天后清理原文件。本轮保留既定的单视频投稿模型，不扩展作者课程与评分。

## 决定

- 投稿编号用于请求幂等，归属绑定网页会话。对象key由服务器随机分配，客户端不能指定key或R2上传编号。8 MiB固定分片，最多500,000,000字节，最后一片允许更小。
- 浏览器先读取MP4容器的视频轨道与时长，接受H.264、不超过1800秒；逐片SHA-256后合成文件指纹，续传必须选择相同文件。只读取moov元数据和单片数据，避免整文件进入内存；moov超过16 MiB时明确拒绝。
- API逐次核对会员和社区开关，签名绑定对象、上传编号、分片编号与长度，有效15分钟。续传和完成以R2 ListParts为准，不相信客户端自报的完成列表。分片完成后HEAD确认大小与video/mp4，再登记为待审核；完成响应丢失时可通过已有对象重试登记。
- 浏览器的编码与时长检查是上传前校验，不是服务端内容鉴定。服务器不转码、不下载媒体流做编码检查，最终内容由管理员预览审核；HEAD只核对对象大小和类型。
- 通过审核时记下管理员和时间，社区开放才同时上架；关闭时仅记为已通过。后续上下架与listing_changes审计同事务追加，不覆盖审核记录。
- 驳回满30天后先提交delete_marked_at，再删R2对象，成功后记deleted_at。失败保留标记，下次重试；cleanup_attempted_at使失败批次轮转，避免阻塞后续到期文件。生产API启动时及每小时运行一批50条，管理员可手动重试；不另建云资源。
- 与评论共用默认关闭的COMMUNITY_ENABLED。关闭时公开列表为空、访客不能取新播放令牌、所有上传步骤被拒绝；本人和管理员仍可私下查看已有记录及预览尚未清理的文件。已签发的短时上传/播放凭证到期前仍可能有效，不能撤销已经发出的凭证。

## 取舍与边界

数据库与R2之间没有分布式事务：外部完成已成功、数据库登记失败时，保留原编号重试；初始化上传后事务失败可能留下未完成的R2上传，依赖桶的未完成分片生命周期清理。R2默认7天终止未完成分片，真实环境仍须核对现有生命周期规则；不在本轮改桶配置。

会员到期不删除历史投稿，只禁止新上传与继续上传。拒绝与删除保留元数据和原因；公开DTO不返回文件指纹、原始key、完整账号编号或审核原因。关闭社区不是删除内容。真实开放条件仍以ADR0005与ticket24为准。
