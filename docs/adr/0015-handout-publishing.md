# 讲义发布直接写库、单请求完成，不复用讲的两阶段对象上传

站主要求课程之外也能上传题面；红线只允许自编题面（答案、真题原文不得上站），题面是 Markdown 文本。现有讲发布为二进制设计：私有计划表、预签名 PUT、对象清理（ADR 0011），对文本过重。

## 决定

- 新增 `PUT /api/v1/publish/handouts/{slug}`：一次请求完成校验与写入 `handouts` 表；新建默认下架，更新不写上架字段。
- 幂等由内容字段与 Markdown 比较得出（服务端另算 `contentHash` 供客户端比较），不入库、不建计划表、不分配对象 key、不产生 R2 对象。
- 契约仍以 zod 单一来源生成 OpenAPI 3.1，并新增独立 JSON Schema `schemas/publish/v1/handout.schema.json`；沿用发布令牌与管理员角色校验（ADR 0011 的权限模型）。
- 发布与上架继续分离：上架走既有管理员接口与 `listing_changes` 审计。

## 取舍

讲义没有版本历史、旧内容清理与上传中断恢复，因为这些机制是为二进制对象设计的；文本体积小、重发成本低，需要历史时再迁移到带版本的 content 表。与讲的两阶段发布并存，按内容类型划边界，不改造已验收的讲发布链路。
