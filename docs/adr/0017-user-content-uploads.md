# 用户上传扩展：投稿单表加 `kind`，用户试卷复用真题试卷模型，文本进数据库

站主 2026-10-31 决定在现有 mp4 投稿之外支持课程手稿（Markdown）、视频字幕（SRT/VTT）和用户题目/试卷（题面+答案+解析）：上传只要求登录，评论、评分、看答案要求有效会员，上传者在自己的内容下免会员评论并可看自己试卷的答案。此前 [ADR 0013](0013-submission-multipart-lifecycle.md) 只覆盖单视频投稿，[ADR 0016](0016-past-paper-publishing.md) 只覆盖站主发布的真题。本 ADR 记录扩展后的数据与权限取舍，细则见[规划 0005](../specs/0005-user-uploads.md)。

## 决定

- **投稿仍是单表**：`submissions` 增加 `kind`（`video` / `manuscript`），视频的 `size` / `duration` / `object_key` 改为可空并按 `kind` 收紧 check；不按内容形态分表。审核、上架、评分、社区开关、清理与归属继续共用一套实现。
- **字幕不是独立投稿**：视频投稿可附带 0–2 条 SRT/VTT 字幕，服务端归一化为 VTT 存入 `submission_subtitles`（Postgres），不产生 R2 对象；手稿正文存入 `submissions.manuscript_markdown`（Postgres），UTF-8 ≤ 1 MiB。只有视频进 R2，对象 key 仍由服务器随机分配（ADR 0013 不变）。
- **用户试卷复用 `papers` + `paper_questions`**，新增 `origin`（`admin` / `user`）、`review_status`（`pending` / `approved` / `rejected`）、审核人/时间/原因与 `rights_confirmed_at`。管理员发布真题仍走原 CLI 路径（`origin='admin'`，直接 `approved`）；用户提交为 `origin='user'`、`pending`、默认下架，`slug` 由服务器生成（`u-` + 12 位十六进制）。
- **公开出口按来源分开**：`/exams` 只列站主真题；用户试卷走独立列表与 `/community/papers/*` 页面。答案接口与答案隔离规则复用 ADR 0016：题面公开，答案只在登录后的单独答案页/接口出现，不进入题面页、列表、摘要、搜索、OG 与 sitemap；上传者本人可看自己试卷的答案。用户试卷不参与评分。
- **审核与上下架复用**：先审后发；审核通过记录审核人和时间，社区开放时才同时上架，关闭时只记为已通过；上架/下架写 `listing_changes`（`target_type='paper'` 已存在）。用户试卷不可编辑或撤回，驳回后重新提交生成新试卷。
- **评论不改造讲评论表**：投稿评论由 ticket 27 的 `submission_comments` / `submission_comment_deletions` 承担；用户试卷评论另建同构的 `paper_comments` / `paper_comment_deletions`，共享 `comment_keywords`、一层回复与删除审计规则。
- **权限**：上传只要求登录（沿用 ADR 0013），不要求会员；评论、评分、看答案要求有效会员；上传者本人在自己的投稿/试卷下免会员评论，并可看自己试卷的答案；不能给自己的投稿评分；管理员审核、上下架、删评论与清理。其他功能不设会员门。
- **用户上传接口不进公开 OpenAPI/CLI 契约**：它们是网页会话 API，规则由 `packages/core` 的 zod 单一来源提供；CLI 仍只有管理员的 `publish` / `publish-handout` / `publish-paper`。

## 取舍

- **单表 + `kind`** 省去复制审核、评分、清理与社区开关，代价是表内出现形态专属可空列，数据库 check 必须按 `kind` 收紧；如果以后出现第三种二进制材料（PDF/图片）再评估子表，不在本轮预建。
- **文本进 Postgres 而非 R2** 沿用 ADR 0015「纯文本单请求直写」：没有对象生命周期、断点续传与清理链路，事务一致；代价是数据库体积（免费库 500 MB）与未来可能的迁移成本，触发条件与阈值记在规划 0005 开放问题。
- **用户试卷复用 `papers`** 复用已验收的题面页、答案隔离、逐题校验与上下架审计，避免第二套答案模型；代价是 `papers` 同时承载两种来源，必须用 `origin` 分开公开出口，并让管理员发布路径保持 `approved` 以不改变既有 CLI 语义。
- **答案隔离不因 UGC 放松**：用户试卷标注「用户投稿」不等于真题，审核通过不等于授权确认；未授权真题内容仍然不得上传或发布，授权责任仍在运营者。
- **不建通用评论/内容多态表**：已验收的讲评论不动，投稿评论与试卷评论各建同构表，换取低风险；重复的约束与审计结构由测试保证一致。

## 与现有 ADR 的关系

- **ADR 0013**：分片上传、服务端核对、审核/清理、上传只要求登录全部保留；本 ADR 只扩展内容形态，并把文件/正文的清理语义复用到文本。
- **ADR 0014**：贝叶斯公式、`C=10`、推荐门槛与禁止自评不变；评分范围扩到已上架的课程材料投稿（视频与手稿），全站基准组成随之变化，用户试卷不评分。
- **ADR 0016**：答案隔离与「会员 / 上传者 / 管理员」放行规则原样适用于用户试卷；新增 `origin` 与权利声明，管理员发布的真题路径不变。
- **ADR 0015**：手稿、字幕与用户试卷都走「结构化/文本直写、跳过对象上传」的先例。
- **ADR 0003 / 0006 / 0011**：视频仍在 R2；公开契约范围不扩大；CLI 权限模型不变。
- **ADR 0005**：社区开放仍受 ICP、备案与运营资质条件约束；用户内容审核不替代资质。
