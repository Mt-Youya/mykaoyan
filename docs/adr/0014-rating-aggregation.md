# 投稿评分使用全站已上架评分作为基准，筛选后仍按同一基准排序

工单23按PLAN§5.4实现贝叶斯平均与推荐。每个账号对每个投稿只有一票，评分可修改；推荐由当前评分推算，不存可由管理员修改的标志。

## 决定

- `m` 是全站当前已通过、已上架且未标记清理的投稿上，所有评分的合并均值；按评分条数加权，不是对每个投稿的均分再做等权平均。全站没有评分时取0。
- `C=10`，`score=(C*m+sum)/(C+n)`。推荐须同时满足n≥5且未舍入score≥4。显示保留两位小数，排序与推荐均使用原始值；显示4.00不代表精确值必然达到门槛。
- SQL在同一查询快照中聚合全站评分、筛选考试科目和可选考点，最后按加权分降序分页。同分时按评分人数、创建时间、编号降序，避免未被评分或仅一票的投稿在同分时占先。
- core纯函数用于返回得分与推荐判断；SQL分页排序使用同一公式和从core导入的C，HTTP测试核对数值、跨科目基准、筛选与下架后的重算。
- 写入绑定网页会话，不接受客户端账号编号。会员状态逐次计算；管理员也须有当前会员期，且不能给自己的投稿评分。锁定投稿后核对上架状态，再用投稿/账号组合主键upsert，和下架写入串行化。
- 会员到期后评分保留并继续参与统计，只禁止新评分与修改。投稿下架后其评分保留，但不参与全站基准与公开排序；重新上架后自然恢复。
- 与评论、投稿共用默认关闭的COMMUNITY_ENABLED。关闭后评分读写被拒绝，公开投稿入口与列表仍由现有开关一起隐藏；不删除记录。

## 取舍

全站基准会随评分修改或投稿上下架变化，因此未被直接评分的投稿得分也可能变化。尚无评分的投稿得分等于m，但人数为0，不能推荐。实时聚合避免缓存与上架状态漂移，代价是每次列表请求都要计算当前全站统计；需要优化时保留同一口径与HTTP验证。
