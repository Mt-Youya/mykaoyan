# CLI 发布使用专用令牌、服务器发布计划和不可覆盖的对象 key

工单 14 需要按内容哈希幂等发布，并保留下架状态。普通进度令牌不能因此自动获得管理员权限。

## 决定

- Agent 令牌新增 `scope`，默认 `progress`；只有管理员的网页会话能创建 `publish` 令牌。发布接口只认发布令牌，并每次查询账号当前角色与吊销状态。原有令牌不升级权限。
- prepare 接收公开契约的课程、章、讲内容；服务器规范化输入并算 SHA-256，保存绑定账号的发布计划。完成发布只能引用计划，不能由客户端传任意对象 key。
- 新对象使用独立 UUID 目录，预签名 PUT 同时签入 Content-MD5、Content-Type 与 If-None-Match，禁止覆盖已上传对象。大小与单次 PUT MD5 ETag 在登记前 HEAD 校验。SHA-256 用于内容版本标识，MD5 用于 R2 单次 PUT 的传输校验；不使用 R2 不支持的 FULL_OBJECT SHA-256 请求。视频单次上传上限 5GB，不自动切成分片。
- 所有新对象确认后，在课程级事务锁下登记内容并递增讲的内容版本。只在新增时默认下架，更新语句不写任何 listed 字段。并发计划基线不符返回 409，禁止旧计划覆盖新内容。
- 写库成功后删除本流程生成的旧对象；失败留在计划 old_keys，可重试完成接口，不回滚新内容。来源不明的历史对象不自动删除。中断计划可能留下未登记的对象，自动清理暂不做，运维须先核对数据库引用与签名过期时间再处理。
- 按已核对的源目录，数学二/408 为课程范围，章路径为章身份，同名 mp4/srt/md 为一讲。稳定标识取课程内相对路径的摘要，不取本机绝对路径；章新增 publish_key，旧章不凭标题自动合并。目录重命名会生成新标识，须在重命名前明确迁移策略。

## 取舍

两阶段发布多一张私有计划表，但把 key 的分配、并发基线与可重试删除留在服务器。独立对象目录会短暂多占空间，但避免签名 URL 重放覆盖正在播放的内容。管理员更换发布令牌不改变发布计划归属，计划仍属于同一账号；撤销管理员角色后立即不能继续发布。

一章逐讲登记，不承诺整章事务；中途失败可重新发布，已完成的同哈希讲直接无变化。不使用课程目录里第三方模板、答案、真题或当前练习解答，配对缺失的材料只报告不上传。
