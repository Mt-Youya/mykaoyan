# 规格 0001：mykaoyan v1（M0–M4）

> 状态：已确认（2026-10-26，测试边界经站主确认）｜分诊标签：`ready-for-agent`｜工单：`.scratch/mykaoyan-v1/issues/`｜术语见 [GLOSSARY.md](../../GLOSSARY.md)｜决策见 [docs/adr/](../adr/)｜规则细节见 [docs/PLAN.md](../PLAN.md) §5

## Problem Statement

考研人的备考资源分散：好的讲解视频在各个平台，自己的错题、复测和学习时长靠纸笔或表格，很难按间隔复测、看出哪些考点还不稳。站主已经自制了数学二和 408 的课程（视频、字幕、讲稿），也有一个只供自己使用的追踪工具，但工具不能跨设备，别人也用不了；考生的 agent 虽然能整理学习记录，却没有地方上传。考生之间也没有一个按考点筛选、由真实考生评分的视频推荐。

## Solution

一个面向大陆考生的网站 `mykaoyan.cn`：

- 任何人都能免费看站主发布的课程和讲义。
- 考生用手机号登录后，可以记录错题并按间隔复测、写每日记录、看今日页和考点进度；也可以用本站公开的进度文件格式，让自己的 agent 通过本站的 skill 或 CLI 生成并上传学习数据。
- 会员（10 元/年，公司注册前由管理员开通或兑换码兑换）可以评论讲、投稿视频、给投稿打分；评分高的投稿成为推荐。
- 词表和单词复习只在考生自己的浏览器里，不上传。

## User Stories

### 访客与浏览

1. 作为访客，我想不登录就看到课程列表，以便判断这个站值不值得用。
2. 作为访客，我想按考试科目进入课程，看到它的章和讲，以便找到我要学的内容。
3. 作为访客，我想在讲的页面直接播放视频并拖动进度条，以便跳到我需要的部分。
4. 作为访客，我想在视频下看到讲稿，并能显示数学公式，以便边看边对照。
5. 作为访客，我想打开字幕，以便在不方便外放时也能看。
6. 作为访客，我想阅读讲义（如速查表），以便快速复习。
7. 作为访客，我想浏览已上架的投稿和推荐投稿，以便看到其他考生认可的视频。
8. 作为访客，我想在手机浏览器上也能顺畅浏览和播放，以便碎片时间学习。
9. 作为访客，我想看到隐私政策和用户协议，以便知道注册后数据怎么处理。

### 账号与登录

10. 作为考生，我想用手机号和短信验证码登录，以便不用记密码。
11. 作为考生，我想第一次用验证码登录时自动注册，以便少走一步。
12. 作为考生，我想在注册时单独看到「个人信息存储在新加坡」的说明并自己勾选同意，以便知情。
13. 作为考生，我想在验证码过期或输错时看到准确的原因，并能重新获取，以便不被卡住。
14. 作为考生，我想在验证码发送太频繁时被告知还要等多久，以便不重复点击。
15. 作为考生，我想登录状态在一段时间内保持，以便不用每次都输验证码。
16. 作为考生，我想退出当前设备，也能单独选择退出所有设备，以便在公共电脑上用完后放心。
17. 作为考生，我想看到自己账号绑定的手机号（脱敏显示），以便确认是哪个号码。

### 学习追踪

18. 作为考生，我想建立备考档案：初试日期、考试科目和目标分，以便站点按我的情况安排。
19. 作为考生，我想设定各阶段的工作日和周末各科分钟，以便有默认的每日计划。
20. 作为考生，我想按天调整某一天的各科分钟和弹性时间，以便应对当天的情况。
21. 作为考生，我想记录一道错题及其订正，并关联考试科目和考点，以便之后复测。
22. 作为考生，我想补录过去订正的错题和已经做过的复测，以便把旧记录搬进来。
23. 作为考生，我想在订正后 2 天收到第一次复测提醒、第一次独立完成后 5 天收到第二次，以便按间隔巩固。
24. 作为考生，我想复测时选择独立完成、提示后完成或不会，以便如实记录。
25. 作为考生，我想在复测没有独立完成时让这道错题从第一次复测重新开始，以便真正掌握。
26. 作为考生，我想看到逾期的复测和逾期天数，而不是被判失败，以便补上。
27. 作为考生，我想写每日记录：各科学习时长、完成事项、明日首要任务和一句复盘，以便回顾。
28. 作为考生，我想补录或修改过去某一天的每日记录，以便记录完整。
29. 作为考生，我想打开今日页就看到今天的各科计划分钟、要做的复测、到期卡和新卡数量、已记录的学习时长，以便知道今天先做什么。
30. 作为考生，我想今日页按「逾期复测 → 今天的复测 → 到期卡 → 新卡」排序，以便先处理最要紧的。
31. 作为考生，我想手动把考点标为未测、学习中或已练，以便反映我的掌握情况。
32. 作为考生，我想已练的考点根据关联错题自动变成待重测或稳定，以便稳定有复测作证据。
33. 作为考生，我想看一周的只读汇总并写下周调整，以便每周复盘。
34. 作为考生，我想换一台设备登录后看到同样的学习数据，以便跨设备使用。

### 词表与单词复习（浏览器本地）

35. 作为考生，我想导入自己的 CSV、TSV 或 JSON 词表，以便复习我自己的词。
36. 作为考生，我想重复导入词表时不丢失已有的复习进度，以便放心更新词表。
37. 作为考生，我想每天先复习到期卡，到期卡清空后最多引入 30 张新卡，以便节奏稳定。
38. 作为考生，我想用 again、hard、good、easy 四档评分，以便调度下一次复习。
39. 作为考生，我想导出浏览器里的私有内容、单词卡和复习记录为一个备份文件，并在另一台设备导入，以便手动迁移。
40. 作为考生，我想导入备份前看到各类条目数并确认，且系统先自动下载一份当前数据，以便误操作后能恢复。
41. 作为考生，我想确认词表和单词卡不会被上传到本站，以便放心导入有版权的词表。

### 进度文件、公开契约、skill 与 CLI

42. 作为考生，我想下载一份包含我全部学习数据的进度文件，以便自己保存或交给 agent 处理。
43. 作为考生，我想在网页上上传一份进度文件替换我的学习数据，并先看到变更摘要，以便知道会改什么。
44. 作为考生，我想上传时如果云端数据在我下载之后被改过就被拒绝，以便不覆盖别处的修改。
45. 作为考生，我想查看进度文件的历史版本列表，以便知道数据何时被改过。
46. 作为考生，我想在本站找到进度文件的 JSON Schema 和接口文档，以便让任何工具按规范生成。
47. 作为考生，我想为自己的 agent 生成一个 Agent 令牌，并能随时吊销，以便安全地授权。
48. 作为考生的 agent，我想按本站 skill 的说明，从考生的备考资料生成合法的进度文件，以便考生不用手写 JSON。
49. 作为考生的 agent，我想在上传前用 skill 自带的校验脚本离线检查进度文件，以便尽早发现错误。
50. 作为考生的 agent，我想用 Agent 令牌读取和上传进度文件，以便持续更新考生的进度。
51. 作为考生，我想用 CLI 登录、拉取、校验、推送进度文件，以便在终端里完成同样的事。
52. 作为外部开发者，我想依赖一个有版本号的公开契约，并知道兼容变更和破坏性变更的规则，以便我的工具不会突然失效。
53. 作为考生，我想 Agent 令牌不能用来登录网页，以便令牌泄露时影响有限。

### 会员

54. 作为考生，我想输入兑换码开通一年会员，以便获得评论、投稿、评分的权限。
55. 作为会员，我想在会员期内再次兑换时，新会员期接在当前会员期之后，以便不浪费时间。
56. 作为会员，我想看到我的会员到期日，以便及时续期。
57. 作为会员，我想到期后已发的评论、投稿和评分保留，以便内容不丢失。
58. 作为考生，我想在不是会员时点击评论、投稿或评分看到开通会员的说明，以便知道怎么获得权限。

### 评论

59. 作为会员，我想在一讲下发表评论，以便提问或分享心得。
60. 作为会员，我想回复别人的评论（只有一层），以便讨论。
61. 作为会员，我想在评论含违规关键词时被直接告知未发布，以便修改。
62. 作为访客，我想看到讲下的评论，以便参考其他人的问题。
63. 作为访客，我想看到被删除的评论显示为「已删除」，以便理解对话上下文。

### 投稿、审核、评分与推荐

64. 作为会员，我想上传一个 mp4 视频作为投稿，选择考试科目、可选考点，并填写标题和简介，以便分享好的讲解。
65. 作为会员，我想上传大文件时看到进度，并在网络中断后继续上传，以便不白传。
66. 作为会员，我想在文件超过 500MB、超过 30 分钟或格式不对时上传前就被告知，以便不浪费时间。
67. 作为会员，我想看到我的投稿处于待审核、已通过或已驳回，以便知道进展。
68. 作为会员，我想给已上架的投稿打 1 到 5 星，并能修改，以便表达我的评价。
69. 作为会员，我想不能给自己的投稿评分，以便评分公正。
70. 作为考生，我想按科目或考点筛选投稿，并按加权评分排序，以便找到好视频。
71. 作为考生，我想只有一两个人打高分的投稿不会排到最前面，以便推荐可信。
72. 作为考生，我想看到投稿的评分人数和加权平均分，以便自己判断。

### 管理员

73. 作为管理员，我想用 CLI 从本地课程目录发布一章或整个课程，以便批量上传视频、字幕和讲稿。
74. 作为管理员，我想重复发布同一份内容时结果不变，以便放心重跑。
75. 作为管理员，我想重新发布内容时不改动我在网页上设置的上架状态，以便发布和上架分开控制。
76. 作为管理员，我想在网页上上架或下架讲、讲义和投稿，以便控制可见内容。
77. 作为管理员，我想审核投稿：通过或驳回并写原因，以便把关内容。
78. 作为管理员，我想被驳回的投稿文件 30 天后自动删除，以便节省存储。
79. 作为管理员，我想删除评论并留下原因记录，以便处理违规内容并可追溯。
80. 作为管理员，我想手动给一个账号开通会员并写原因，以便测试或补偿。
81. 作为管理员，我想批量生成兑换码并查看每个码是否已兑换、被谁兑换，以便管理发放。
82. 作为管理员，我想维护评论关键词列表，以便调整过滤规则。

### 运维

83. 作为站主，我想每次部署后自动检查首页、接口和数据库连接，以便发现坏的部署。
84. 作为站主，我想数据库每天自动备份并保留 30 天，以便出事时能恢复。
85. 作为站主，我想 ECS 资源持续超过 80% 时收到告警，以便及时扩容。
86. 作为站主，我想在 M0 拿到国内多地的访问和播放实测数据，以便判断跨境架构是否可用。
87. 作为站主，我想任何密钥都不出现在公开仓库和镜像里，以便仓库可以公开。

## Implementation Decisions

**运行拓扑**（[ADR 0001](../adr/0001-runtime-topology.md)）

- 前端 TanStack Start 与后端 NestJS 都以 Node 进程跑在大陆 ECS，Caddy 按路径分发：`/api/*` 给后端，其余给前端。同一域名，不需要跨域配置。

> 更新（2026-10-28）：按 [ADR 0010](../adr/0010-worker-api-proxy.md)，前端改为留在 Cloudflare Worker `mykaoyan-web`，ECS 只跑 NestJS API 并经 Worker 反代 `/api/**`；ECS 地域为广州（华南 3）。原「前后端同一台 ECS」的方案不再采用。
- 数据库是 Supabase 新加坡区域的 Postgres，只当普通 Postgres 用（[ADR 0002](../adr/0002-supabase-as-plain-postgres.md)），经 Supavisor transaction 模式连接。
- 视频在 R2，由媒体 Worker 校验 HMAC 播放令牌后直接回给浏览器（[ADR 0003](../adr/0003-video-on-r2.md)）。

**模块**

- `core`：所有数据结构的 zod 定义；纯函数领域模型，包括复测推算、单词复习调度、计划推算、今日页排序、考点进度推算、会员判断、贝叶斯评分与推荐判断、进度文件的校验与变更摘要、`LocalDate`。不依赖任何框架和 IO。
- `db`：Drizzle 表结构与 SQL 迁移。
- `api`：NestJS 模块按领域划分（accounts、catalog、membership、comments、submissions、ratings、progress、media）。控制器只解析参数，服务层做权限判断和业务。
- `web`：页面与交互；服务端渲染时带 cookie 调 `api`，并把 `Set-Cookie` 转回浏览器。浏览器本地的词表、单词复习和备份在这里实现，调度规则来自 `core`。
- `media-worker`：只校验令牌和处理 Range、条件请求。
- `cli`：Rust，类型从 OpenAPI 生成。
- `skills/mykaoyan`：进度文件说明、零依赖校验脚本、空白模板。

**数据模型要点**

- 账号与登录方式分表；账号以已验证手机号为准；登录方式表预留 QQ、微信（含 unionid）、支付宝。
- 会员资格由会员期推算，不存「是否会员」字段。会员期带来源（manual、code，以后加支付）。兑换码一次性，兑换和生成会员期在同一事务里。
- 学习数据以「每个账号一份进度文档 + 只追加的历史版本」存储，与进度文件格式一致；错题的复测状态不单独存，由记录推算。
- 投稿状态：待审核、已通过、已驳回；上架状态与内容字段分开，发布命令只写内容字段。
- 评论只有一层回复；删除保留操作记录。

**公开契约**（[ADR 0006](../adr/0006-public-contract-from-zod.md)）

- 进度文件 v1：以旧 kaoyan `progress/v1` 为起点，`app` 为 `"mykaoyan"`。
- `GET /api/v1/progress` 返回文档与 `ETag`；`PUT /api/v1/progress` 必须带 `If-Match`，不匹配 412、缺失 428，成功返回变更摘要；`GET /api/v1/progress/revisions` 返回历史版本列表。
- Agent 令牌只能访问 `/api/v1/*`，不能建立网页会话；管理员令牌另有发布接口。
- 错误统一为 `application/problem+json`；未登录 401，无权限 403。
- JSON Schema 2020-12 与 OpenAPI 3.1 由 zod 生成并提交进仓库，CI 检查无差异。

**登录**（[ADR 0004](../adr/0004-phone-first-login.md)）

- Better Auth 加 `phoneNumber` 插件，验证码由阿里云号码认证发送和校验；验证即注册；同一手机号发送频率受限。
- 注册时单独取得个人信息出境同意，并记录同意时间与政策版本（[ADR 0005](../adr/0005-accepted-compliance-risks.md)）。

**媒体**

- 播放令牌按「账号或访客 × 讲或投稿」签发，短时有效，到期前续签且不打断播放。
- 投稿上传：`api` 签发预签名分片上传，浏览器直传 R2，完成后 `api` 读取对象元数据确认大小和类型再登记。

**规则**：会员、评论、投稿、评分推荐、复测、单词复习、计划与今日页的具体规则见 [PLAN.md §5](../PLAN.md)。

## Testing Decisions

**好测试的标准**：只通过外部行为断言——HTTP 请求与响应、纯函数的输入与输出、浏览器里用户看到的东西；不断言内部调用次数、私有字段或表结构细节。每个新守卫要做一次变异检查，确认被测行为坏掉时测试会失败。

**测试边界（已确认）**

1. **主边界：`api` 的 HTTP 接口，连真实 Postgres。** CI 用临时 Postgres 容器，从空库跑全部迁移后启动 NestJS，测试只发 HTTP 请求。覆盖：登录（短信发送用替身）、权限矩阵（访客、账号、会员、过期会员、管理员 × 每个写接口）、「别人的数据读不到、写不进」、进度文件 `If-Match` 并发、兑换码并发兑换只有一个成功、发布命令不改上架状态、评论关键词拒绝、投稿状态流转。
2. **`core` 纯函数**：复测推算、单词复习调度、计划推算、今日页排序、考点进度、会员期叠加、贝叶斯评分与推荐门槛、进度文件校验与变更摘要。用表格驱动的用例，日期按 Asia/Shanghai。
3. **公开契约**：生成的 JSON Schema 和 OpenAPI 与提交的文件无差异；虚构 fixture（有效与无效各一组）用独立校验器（ajv）验证；skill 的校验脚本与 schema 对同一组 fixture 给出相同结论。
4. **`media-worker` 的请求处理函数**：Range、416、304、412、401 且未读 R2、令牌过期；R2 替身按真实返回形状建模，并在 M0 用真实桶校准一次。
5. **少量浏览器端到端**：手机号登录、播放视频并拖动、上传进度文件、会员评论。其余 UI 手动验证。

**沿用的先例**：旧 kaoyan 的进度文件契约测试与 fixture 组织方式、架构依赖规则测试、`accounts` 迁移在临时 Postgres 上的幂等与权限测试。

## Out of Scope

- 任何支付渠道，以及 QQ、微信、支付宝登录（M5，公司注册之后）。
- App 与小程序（远期，见 PLAN §8）。
- 邮箱、Google、GitHub 登录与邮件通知。
- 视频转码、HLS、DRM、防下载。
- 进度文件的细粒度写接口（逐条增删错题、复测）。
